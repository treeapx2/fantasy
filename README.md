# Fantasy Football Draft Prep App

Compiles multi-source rankings/analysis by player, supports personal rank/tier overrides
and risk/upside notes persisted across sessions, and (later) a draft-strategy layer and
an in-season lineup management tool.

## Status

**Phase 1 complete:** UDK mechanical extraction → canonical dataset.
**Not yet built:** UDK analysis/notes synthesis, app UI, ESPN comparison layer, draft
strategy model, in-season tool.

## Repo layout

```
data/
  sources/
    udk/
      players_raw.json     UDK rank/tier/bio/ADP/projection columns, as extracted. Mirrors
                            the source layout — do not hand-edit; re-run build/extract_udk.py.
      field_mapping.json   udk raw field -> canonical field. Add an entry here before a new
                            raw field can flow into data/canonical/players.json.
    espn/                  (not yet created — Phase 4)
  canonical/
    players.json           UI-facing merged dataset. Generated by build/build_canonical.py.
                            Never hand-edit — it's fully regenerated on every build.
  user/
    my_ranks.json           Your rank/tier overrides, keyed by player_id. Independent of
                             any source's rank — never overwritten by a rebuild.
    notes_staging.json      Your raw dropped-in notes, unsorted, timestamped. You add to
                             this; on each update pass I sort entries into risk_upside_notes.json.
    risk_upside_notes.json  Per player: {risk: {udk: [], espn: [], user: []}, upside: {same}}.
                             Your notes stay in their own "user" sub-list — never merged into
                             or indistinguishable from source-derived notes.
build/
  extract_udk.py      Source of truth for UDK's raw data — the numbers live here as Python
                       tuples (versioned, diffable), not hand-typed JSON. Re-run to regenerate
                       data/sources/udk/players_raw.json.
  build_canonical.py  Merges all data/sources/*/players_raw.json into data/canonical/players.json
                       via each source's field_mapping.json. Reports unmapped fields rather than
                       silently dropping them. Also scaffolds (never overwrites) data/user/*.
```

## Adding a new source (e.g. ESPN) or a new field

1. Extract the source's raw data into `data/sources/<source>/players_raw.json` (same shape:
   `{source, source_label, source_date, players: [...]}`, each player carrying whatever
   fields that source has).
2. Write `data/sources/<source>/field_mapping.json` mapping that source's raw field names to
   canonical names (reuse an existing canonical name where it's the same underlying stat,
   e.g. both UDK and ESPN's "bye week" should map to canonical `bye`).
3. Run `python3 build/build_canonical.py`. Any raw field not yet in the mapping is printed
   as **unmapped** — it exists in the raw data but won't reach the UI until you add the
   mapping entry and, separately, add UI support for it. Two deliberate steps, nothing
   silent.

## player_id / cross-source name matching

`player_id` is a slug of `name-team-position`. UDK and ESPN will likely spell some names
differently (suffixes, hyphenation, etc.) — `build/build_canonical.py` has a `NAME_ALIASES`
dict for exactly this, populated as mismatches are found once ESPN is added. Not an issue
yet since UDK is the only source.

## Known data gaps in the current UDK extraction

- **Tag icons** (My Guy / Value / Sleeper / Breakout / Bust / Injury Concerns): the PDF
  renders these as small glyphs that don't survive text extraction reliably across 312
  rows. Only **Rookie** is auto-tagged (derived from `exp == 0`, which is unambiguous).
  The others are left as an empty `tags` array for now. If you want them, the honest fix is
  a dedicated visual re-pass over the PDF pages rather than a guess.
- **TE games/finish_2025**: cropped out of the source page layout for all 54 TEs — null for
  every TE record, not a sampling gap.
- **Rashee Shaheed (WR #54)**: source PDF lists `games: 18`, which isn't possible in an NFL
  season (max 17). Kept as-is from the source with this flag rather than silently "corrected"
  — worth a gut-check against the actual PDF if it matters for your notes.
- **Risk/upside notes**: not yet synthesized. `data/user/risk_upside_notes.json` is scaffolded
  with empty lists for every player, ready for the next phase.

## Validation

`build/extract_udk.py` and `build/build_canonical.py` are safe to re-run any time. After any
change, a quick sanity check:

```python
import json
d = json.load(open("data/canonical/players.json"))
assert d["player_count"] == 312  # 36 QB + 91 RB + 131 WR + 54 TE as of the 8/30/2026 UDK
```
